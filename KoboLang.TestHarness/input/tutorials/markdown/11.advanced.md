# Advanced Capabilities in Kobo

## Interop
Kobo, like every .NET platform language, supports interop via p/invoke.  Functions that participate in
p/invoke calls are declared as ```external```. When external is used, a source attribute indicating the source
library of the external function must be provided.  At present kobo only supports native libraries.

In the following sample, MessageBoxW is a win32 api exported function inside of the user32.dll library.

```kobo

//interop
[source("user32.dll")]
external:int MessageBoxW(
    nint hwnd,
    string text,
    string caption,
    uint type)

```

You call the external function like any other function in kobo

> Note: This only works in windows 

```kobo

//usage
// MessageBoxW(
//     IntPtr.Zero,
//     "Hello from C#!",
//     "P/Invoke Example",
//     0);

```

## Scoping object instances
The `scope` keyword in Kobo provides an explicit way to define a localized execution context, grouping related variables and 
operations within a clearly defined boundary. It improves code organization, controls variable visibility and lifetime, 
and makes the intent and boundaries of an operation easier for both developers and AI agents to understand.

Take the class below expressed as an object *named_item*

```kobo

//scoping (to quickly set properties in a class)
class:NamedItem
{
    [public]
    property:string Name

    [public]
    property:int ID
    
    [public]
    property:string ItemType

    [public]
    indexer:char Characters[int i] => Name[i]

    [public]
    operator:NamedItem =(string name)
    {
        return new NamedItem
        {
            Name = name
        }
    }

    [public]
    operator:NamedItem =((string name, int id) item)
    {
        return new NamedItem
        {
            Name = item.name,
            ID = item.id,
        }
    }


    [public]
    function:void ScopedFunction()
    {
        Print("this is a scoped function")
    }

    
}

//using a scope to set multiple properies of an object
//without having to keep using its reference
var named_item = new NamedItem()

```

A scope could be created for person, where a receiver does not need to be used to access its properties

```kobo
var:char character = 'o'
scope(named_item)
{
    .Name = "david"
    if .ID == 0
        .ID = 10
    .ItemType = "Planet"

    .ScopedFunction()

    character = .Characters[0]
    Print("\nUsing print in a scope: ${character}\n") //prints d
}

```

## Kobo Queries
Kobo provides expressive, SQL-inspired query syntax for working with collections and data sources through .NET LINQ. 
Developers can filter, join, group, sort, and project data using readable, declarative expressions, while supporting 
operations such as `skip`, `take`, and pipeline-based aggregations. Kobo queries integrate with the .NET ecosystem, 
enabling familiar LINQ capabilities with a more natural and concise syntax.

In the following sample we perform a basic query and join.  Note the use of ```project``` to define what values of the target item
are projected out of the resulting list.  If no projection section is specified the entire item is projected out by default.

> Note:  Projection can only happen after the select statement. You cannot access any properties of planet inside of the select 
statement.

>Note: **kobo query statems require a semicolon to end the declaration.**

In the following following code,  planets_that_start_with_m is an ```IEnumerable<NamedItem>```

```kobo

//language queries
var:List<NamedItem> planets_list = ["my","very","educated","mother","just","served","us","nine","pickles"]
var:List<NamedItem> names = ["just","my","luck"]
var planets_that_start_with_m = select planet from planets_list
                                join name from names on planet == name
                                where planet.Name.StartsWith('m')
                                project planet;

Print(planets_that_start_with_m) //an IEnumerator
Print()


```

## Skipping
Kobo  supports ```skip``` and ```take``` keywords to return slices of the data from the
query operation

```kobo

//skip and take (and calling functions on the result using pipe)
Print("Skip and take")
var list_of_planets = select planet from planets_list
                            skip 3 take 5
                            project planet;

Print(list_of_planets) //an IEnumerator

foreach item in list_of_planets
    Print("-${item.Name}")

Print()

```

## Kobo queries support grouping

```kobo

Print("Grouping")
var:List<NamedItem> full_list = [("my",3),("very",1),("educated",2),"mother","just","served",("us",3),("nine",5),"pickles"] //slicing collections into other collections
var groups = select item from full_list
             group item by item.ID into g
             project g;
             
foreach current_group in groups
    Print("-${current_group.Key} (${current_group.Count()} item(s))")

Print()

```

## Piping results
When the query is working against in memory lists returning IEnumerable is fine.  In scenarios where an IQueryable
data structure is returned there is a need to make additional call to actually execute the query and return a result.
Typically in C# this happens by wrapping the entire statement in parenthesis and calling ```ToList()``` on that.  Kobo
introduces the pipe (|) operator to push the results of a query inot additional operators that can 
be used to further process the results.  In the sample below the query is piped
to a ```list``` command that returns the result as a ```List<NamedItem>```

```kobo
Print("Piping results")
list_of_planets = select planet from planets_list                               
                                project planet | list;

Print(list_of_planets) //a list

foreach item in list_of_planets
    Print("-${item.Name}")

Print()


```

piping also extends to other kinds of operations.  You can do count, list, min, max, and average

```kobo

//get the average ID value
Print("Piping average")
var average = select item from full_list
             project item | count; //try other pipe operations here: count, min, max, average

Print(average)
Print()


                  
```
